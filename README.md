# BookingTelegramBot

Telegram-бот для бронирования дат в конкретном топике группового чата: календарь на N дней вперёд, кнопки вместо команд, система «спонсоров» с приоритетом бронирования и заметка к брони, видимая другим пользователям.

## Возможности

- 📅 Календарь на ближайшие `DAY_DELTA` дней (по умолчанию 14) с инлайн-кнопками.
- ✅ Бронирование свободной даты и отказ от собственной брони.
- 💬 При бронировании можно оставить сообщение (например, во сколько вас искать) — его увидят другие пользователи, открыв эту дату.
- 👑 Спонсоры могут бронировать даты, уже занятые обычными пользователями (перебивая их бронь); обычные пользователи не могут перебить бронь спонсора.
- 🔒 Бот реагирует только в заданном чате и топике (`ALLOWED_CHAT_ID` + `ALLOWED_THREAD_ID`), остальные сообщения игнорируются.
- 🗑️ Сообщение с календарём можно закрыть — кнопка «Закрыть» доступна только автору сообщения.
- Данные хранятся в SQLite (`reservations.db`), схема создаётся автоматически при первом запуске.

## Команды

| Команда | Кто может | Описание |
|---|---|---|
| `/book` | все | Открыть календарь бронирования |
| `/help` | все | Список доступных команд и текущие права пользователя |
| `/sponsor @username` или `/sponsor <user_id>` | супер-админ | Выдать пользователю статус спонсора |
| `/unsponsor @username` или `/unsponsor <user_id>` | супер-админ | Забрать статус спонсора |

> Чтобы бота можно было найти по `@username`, пользователь должен хотя бы раз вызвать `/book` в разрешённом топике — так он попадёт в базу.

## Как работает бронирование

1. `/book` открывает календарь — дата помечена 📅 (свободна), ❌ (занята) или 👑 (занята спонсором).
2. Выбор даты показывает её статус и, если бронь занята, текст заметки, оставленной автором брони.
3. При нажатии «✅ Забронировать» бот просит ввести сообщение для брони (или нажать «⏭️ Пропустить» / «❌ Отмена»). Введённый текст сохраняется вместе с бронью и отображается всем, кто откроет эту дату.
4. «🗑️ Отказаться от брони» доступно только автору брони и полностью её удаляет.

## Установка

Требуется Python 3.9+.

```bash
git clone https://github.com/Pi4yka/BookingTelegramBot.git
cd BookingTelegramBot

python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

## Настройка

Скопируйте `.env.example` в `.env` и заполните значения:

```bash
cp .env.example .env
```

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от [@BotFather](https://t.me/BotFather) |
| `SUPER_ADMIN_ID` | да | Telegram `user_id` супер-администратора |
| `ALLOWED_CHAT_ID` | да | ID чата, в котором работает бот |
| `ALLOWED_THREAD_ID` | да | ID топика (темы) внутри чата |
| `DAY_DELTA` | нет | Сколько дней вперёд показывать в календаре (по умолчанию `14`) |

Узнать `ALLOWED_CHAT_ID` и `ALLOWED_THREAD_ID` проще всего, включив у бота вывод `update` в лог (например, временно логируя `update.effective_message`) и написав сообщение в нужном топике.

## Запуск

```bash
python main.py
```

При первом запуске бот сам создаст `reservations.db` и таблицы в ней.

## Тесты

Бизнес-логика бронирования (`booking_service.py`) вынесена отдельно от Telegram-хендлеров и покрыта юнит-тестами:

```bash
python -m unittest discover -s tests
```

## Структура проекта

```
main.py               # хендлеры Telegram (команды, кнопки, диалоги)
db.py                 # доступ к SQLite (пользователи, брони)
booking_service.py    # чистая бизнес-логика бронирования (без Telegram и БД)
tests/                # юнит-тесты booking_service.py
```
